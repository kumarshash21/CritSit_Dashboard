      Bug + Process Gap combined
      How are these KPIs calculated? (full rules)
      • Ticket → GM — Share of Total SF Cases that carry a link to any GM-XXX EA, regardless of when the EA was created.
      • Ticket → TEO — Share of Total SF Cases linked to a Month EA that TEO resolved (resolved by TEO users + status ∈ {Done, Unable to Conclude, No longer an issue}). EA → Ticket (TEO) is the same EA set expressed against all Month EAs instead of SF cases.
      • Ticket → QA — Share of Total SF Cases linked to a Month EA that reached QA (not TEO-resolved). EA → Ticket (QA) is the same EA set expressed against all Month EAs instead of SF cases.
      • EA → Bug — Of Month EAs concluded, the share that closed as Known/New Bug, including duplicates chased back to a bug.
      • Bug Rejection % — Of EAs concluded directly as Known/New Bug, the share whose linked bug was later rejected.
      • EA → PG — Of Month EAs concluded, the share that closed as a Process Gap.
      • EA → Improvements — Of Month EAs concluded, the union of Bug and Process Gap outcomes.

      What does each bucket row mean?
      • Total SF Cases — SF cases created in the selected period matching scope: Type ∈ ('Incident') AND Product_Type__c ∈ ('RTP', 'TTP'). Narrowed further by the active Pod/Severity filters.
      • SF — Any GM link / Unique EAs — SF: cases pointing to ANY GM-XXX regardless of when the EA was created. GM: distinct EA keys those cases point to (de-duplicated).
      • SF Linked w/ Month EAs / Month EAs — SF: cases whose linked EA was created in this period (IST). GM: distinct Month EAs = In Progress + Concluded.
      • SF Cases / EA — concluded from TEO — Of the Month EAs, the subset matching the TEO filter (resolved by TEO users + status ∈ {Done, Unable to Conclude, No longer an issue}). SF: cases linked to those EAs.
      • SF Cases / EA reached to QA — Month EAs NOT in the TEO-resolved filter set — the QA-bound work pool. By construction equals Month In Progress + Month Concluded. Broader than the Ticket → QA KPI numerator (that also requires a changelog transition to QA analysis in progress).
      • Month EAs — In Progress / Concluded — Status split of Month EAs (Concluded = Done/No longer an issue/Unable to Conclude, AND not TEO-resolved). Concluded is the EA → Bug denominator and the TEO Leakage universe.
      • SF Linked w/ Old EAs / Old EAs — SF: cases (in-period) whose linked EA was created OUTSIDE the period. GM: distinct Old EAs = Unique EAs linked w/ SF − Month EAs. By construction Month + Old = Unique.
      • Old EAs — In Progress / Concluded — Status split of Old EAs.
